# Durable-DAV — Web SPA

Scope: `apps/web/**`. Parent index: `../../AGENTS.md`.

- Vite + React 19 SPA (`src/main.tsx`: `BrowserRouter` → `SpaApp`). Build embeds `dist/index.html` into `apps/api/src/generated/spa-shell.ts` (Vite plugin `spa-shell-embed`; never edit generated file; `scripts/ensure-spa-shell-stub.mjs` creates the empty stub on install).
- **Rebuild before deploy: `pnpm run build`.** The API worker serves `SPA_HTML` from the *last local build*, and both `dist/` and `apps/api/src/generated/` are gitignored — so a source fix here is inert until `vite build` runs again. This is not hypothetical: a `dist/` built before the `DAV:href` change kept shipping the old 2-arg `parseMultistatus`, which left `/owner/volume` on every path. The bucket browser then rendered the volume root as a row inside the volume root and 404'd on every file and folder. `scripts/verify-spa-shell.mjs` (in `pnpm run checks`) catches a missing/stub/mismatched artifact; the stale-but-self-consistent case is covered at the source level by `test/integration/api/SpaBrowserPlane.int.test.ts`.
- The bucket browser's contract with the server is **path addressing**: `davXml.parseMultistatus` strips the `/owner/volume` base from `DAV:href` (RFC 4918 §8.3) to recover the volume-relative `path`, and that `path` is fed straight back into the next request URL. Always pair "parse a real 207 body" with "use the parsed `path` in a real request" — a disagreement between the two halves is invisible when either is checked alone.
- `SpaApp.tsx` — thin composition root: `useCurrentUser` + `useSpaLanguage` + `useNotice` hook slices, `Header`/`NoticeBar`, then `SpaViewRouter` (no data fetching in router).
- `components/layout/SpaViewRouter.tsx` — routes: `/` (Dashboard or Landing), `/new` (gated by `Unauthorized`), `/:owner/:volume` (`VolumeView`, subpath in `?path=` so deep file URLs never collide with WebDAV `GET`, settings in `?tab=settings`), `/settings` (gated user settings, no tokens), `/:username` (`ProfileView`), `*` (localized 404 `Card`). Views in `src/views/`; shared `ui/` primitives in `src/components/`.
- API access: `src/lib/api.ts` + `src/services/*` (`volume/credential/user/profileService`) + `src/lib/davXml.ts` (PROPFIND multistatus parser) + `src/services/davClient.ts` (PROPFIND/GET/PUT/MKCOL/DELETE/COPY/MOVE over `/:owner/:volume`); `src/lib/format.ts`, `src/lib/davPage.ts`, `src/lib/constants.ts`, `src/types.ts`.
- **Paged bucket browse**: `listDirectory` returns a `DavListing` (`entries` + `page`/`limit`/`total`/`paged`), not a bare array, and requests `?page=&limit=` on the browser plane. Page membership is the **server's**: the DO orders by `is_dir DESC, name COLLATE NOCASE, name` and hydrates only the page's children, because `nodeInfo` is a `statInner` + a `dav_nodes` read + a lock query + a props read *per entry*. Two consequences worth knowing: `parseMultistatus`'s client-side sort is now cosmetic *within* a page (it cannot reorder across a boundary), and `X-Dav-Page-Count` is the presence marker — an absent header means the server does not page, so the body is the complete listing and the pager renders nothing. Page state lives in `?page=` (shareable, resets to 1 on folder change); page size in `localStorage` (a preference, not navigation state). Both are clamped on read because both are user-supplied, and again in the DO because that is the enforcement point. **Offset paging is only stable while the collection is unchanged** — a concurrent insert can shift an entry across a boundary — which is why the pager has a refresh rather than a cursor.
- Per-bucket settings: `src/components/volume/VolumeSettingsTab.tsx` (General description + Git-style Danger Zone delete) + `HrefPrefixModeCard.tsx` (Link Prefix: `base` vs `root` href anchoring for client compatibility) + `VolumeCredentialsCard.tsx` (per-bucket Basic credentials, copy-once password, read-only checkbox at creation + a per-row Make Read-Only / Allow Writes toggle) + `VolumeReplicationCard.tsx` (scheduled replication: target, mode, interval, Sync Now, and the decision trail). The toggle is **optimistic** with a revert on failure, and the reason is inherent to the feature: the credential is a bearer secret the client has already cached, so the server cannot force the client to forget it — the toggle is a policy statement that takes effect on that client's *next* request, not a revocation. The browser plane is not covered by the flag (uploads here run as the owner via Access). The bucket browser works under either mode — `davXml.parseMultistatus` strips the prefix when present and copes without it, and `davClient.entryUrl` builds browser-base URLs regardless — so the card only changes what third-party clients see.
- **Replication's four modes are a per-target choice, not one global setting** (`VolumeReplicationForm.tsx`, `REPLICATION_MODES` in `replicationService.ts` — mirrored from the server's closed list, and `t('replication.mode.${mode}')` reads a `select` whose value must match an `<option>`): `copy-only` is a one-way push that never imports, so a corrupted remote copy cannot overwrite the original; `pull-only` is the one-way **import**, where the remote is the sole writer and nothing is ever pushed back; `sync` is two-way with the newer `mtime` winning and `keep-both` as the fallback when it cannot decide; `keep-both` preserves the loser as `<name>.conflict-<seconds>` and never overwrites anything. **`mirrorDeletions` is a checkbox rendered only under `pull-only`**, unchecked by default, and sent only in that mode — the server answers 400 for it anywhere else, so it is derived from the mode rather than being a control that can stay ticked while the mode changes underneath it. It is the one control in the settings UI that can make a sync *delete* a file the bucket holds, which is why it sits below the mode explanation rather than above it. `VolumeReplicationRow` badges it **Exact Mirror** / **Safe Copy** per target, because that is the single fact an owner must know before uploading anything to a bucket under a `pull-only` target. **The credential form (`VolumeReplicationCredentialForm.tsx`) exists because the server used to answer a malformed credential with an error telling the owner to rotate it, and nothing in the browser could do that** — `POST .../credential` was there and correct, and uncalled. An instruction the interface cannot act on is worse than a clear failure, because it costs the owner the one thing they cannot get back: time. It is rendered only for `targetKind: 'dav'` (a `dav-volume` target goes over DO RPC with no credential, so the control would promise something the server has no column for) and only one at a time, since the stored value is never readable back and two open forms invite a password into the wrong target. It asks for the **username again** even when only the password changed, because the username lives inside the sealed blob rather than in a column of its own; that is the honest cost of the storage decision and it is stated here rather than discovered as a 400. `VolumeReplicationRow` renders a `<div>`, not the `<li>` it used to be, because the card now wraps each row together with its credential form in one `<li>`. `VolumeReplicationDecisions` reads a conflict's **`kind`** — a `deletion` (a resource that no longer exists on either side) and a `conflict` (two edited versions reconciled) answer different questions, and the card must not present them as the same event. `services/replicationService.ts` mirrors `VolumeReplicationService.allowedIntervals()` client-side; both lists must change together, which is why the intervals are a closed list rather than a free integer (see the root guide on the shared sweep budget).
- i18n: `src/i18n.ts` (i18next + `react-i18next`) — `SUPPORTED_LANGUAGES` (English-only today; grows bundle-by-bundle under `src/locales/<tag>/translation.json`, enforced by `pnpm run validate:locales`), single `canonicalizeLanguageTag` + `normalizeLanguage`, `detectInitialLanguage` (stored `durable-dav-lng` → `navigator.language` → `en`), `loadLanguage` (static `import.meta.glob` per-locale chunks, falls back to `en` for unshipped bundles).
- English UI text uses Title Case. Pure helpers are unit-tested from the root suite (`src/lib/davXml.ts` via `test/web-davxml.test.ts`).

- **`useCopyToClipboard` is the only clipboard handler** (`src/hooks/useCopyToClipboard.ts`), used by `ReadOnlyField` (copy-once credential password) and `TypeToConfirmModal` (name to retype before a destructive action). It reports `copied` **only after the write resolves**, and both call sites had this wrong in different directions: one showed the ✅ unconditionally — a false success for a denied permission or a missing clipboard, which for a secret reveal means the user walks away believing they have it — and the other fixed that while leaking an uncleared `setTimeout` that set state on an unmounted modal. Do not hand-roll a clipboard call; the honesty of the feedback is the hook's whole job.
- **The SPA must never assert "empty" when it does not know.** `davXml.parseMultistatus` throws on a body that is not a multistatus, and keeps the self response when it is a *file* (`VolumeFileList` renders `entries.length === 0` as the positive assertion "Empty Folder", so an unparseable body answered as `[]` stated a falsehood — and a `Depth: 1` PROPFIND on a file, which is conforming per §9.1, contains only the self response, so a share link to a file rendered as an empty folder). An empty *collection* is distinguished by its `resourcetype`, not by the response count.
- **Destructive DAV operations send `Overwrite: F` by default** (`davClient.moveEntry`/`copyEntry`) and translate the `412` into an explicit `VolumeOverwritePrompt`. With `Overwrite: T` the DO removes the destination before creating the source, so renaming `a.txt` to `b.txt` deleted `b.txt` and its contents with no prompt — while every other irreversible action in the SPA is gated.
- **`useCurrentUser` keys its fetch on a `reloadKey`, never on a callback prop.** An inline arrow from `SpaApp` gave the effect a new dependency every render, and the unguarded `setUser(me)` with a freshly-parsed object never bails out, so the shell issued an unbounded stream of `GET /user/me`. `onError` is read through a ref so a caller cannot reintroduce it.
- **`davPage.readStoredPageSize` snaps to an offered size.** A `<select>` whose `value` matches no `<option>` renders blank, and the preference is durable, so a corrupt `localStorage` entry produced an empty dropdown and a range reading "1–1 of 12 431". The pager is also gated on `hasEntries`, because a failed folder load leaves `total` describing the previous folder.
