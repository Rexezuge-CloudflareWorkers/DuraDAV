# Durable-DAV — API Worker

Scope: `apps/api/**`. Parent index: `../../AGENTS.md`.

- `src/index.ts` — `fetch`/`scheduled` via `DurableDavWorker`; re-exports `CronTasksWorker`, `DavVolumeWorker` from `@durable-dav/background` for DO bindings.
- `src/workers/DurableDavWorker.ts` — Hono routes (no file-routing). `src/types.d.ts` — global `Env`.
- `src/workers/doStubs.ts` — `getVolumeStub(env, owner, volume)` (`DAV_VOLUME.getByName(normalizeVolumeKey)`). Nothing else; the `ensureVolume` this file used to be documented with does not exist.
- `src/workers/routes/davForwardHeaders.ts` — the single header set both front-door planes hand the DO, and the only place allowed to set `X-Dav-Page*`. Every `X-Dav-*` rule is "overwrite, never inherit" (the DO has no auth of its own), plus `Authorization` and an unresolved `Destination` stripped. It was written twice — once per plane — and the two drifted, which is how a caller-set `X-Dav-Page` reached the DO on one plane only.
- `src/middleware/` — `MiddlewareHandlers.userAuthentication()` (`/user/*` via `AccessAuthService` + `UserService.upsertUser`, which sets **both** `AuthenticatedUserEmailAddress` (sign-in address: display, rate-limit key) and `AuthenticatedUserId` (account key: authorization) from one resolution) + `DavAuth.davAuthForVolume()` (bucket Basic `username:password` via `DavCredentialDAO.getActiveByUsername` + `verifyCredential` + volume-id binding + expiry check + `last_used_at` touch + opportunistic legacy-SHA256 rehash; public anon reads via `DavPermissionService.getRole(null, volume)`; 401 with `WWW-Authenticate: Basic` on fail; `DatabaseError` fails closed to 503).
- **Verification tiers** — `credentialVerifier.ts` owns the ordering and is the single entry point for every presented password; `credentialMemo.ts` is the per-isolate cache. `DavAuth` calls `verifyCredential(c.env, username, password, passwordHash)` and **passes the stored hash in** rather than letting the verifier look it up: the caller keeps ownership of the D1 read, so authorization always sees a freshly-read row and only the expensive derivation is reused. A missing `DAV_AUTH` binding or a failed hop falls back to a local derivation — a CPU overrun is strictly better than locking a valid credential out. Rebalancing the tiers (or making the DO mandatory) means editing this one function. `DavAuthResult` carries `userEmail`/`userId` resolved from the volume's `owner_user_id` — never the frozen `owner_email` anchor, which for a re-registered address is an opaque `anchor-…@users.invalid`.
- `src/workers/routes/DavVolumeListCache.ts` — the per-owner volume-list KV entry, keyed on the **account id**. An email-keyed entry is orphaned by an address change: the new address misses and the old entry sits under a key no invalidation can name again. Split out of `DavReadCache` to keep that rule next to the three functions that depend on it.
- `src/workers/routes/` — `DavRoutes` (`/:owner/:volume` + `/:owner/:volume/*` for all `SUPPORT_METHODS`, auth then `stub.fetch` forward with `X-Dav-Base/X-Dav-Path/X-Dav-Href-Prefix-Mode/X-Dav-User` + CORS) + `davDestination.ts` (`resolveDestination` — the single `Destination` canonicaliser both planes use; rejects dot-segments on the **raw** header before `new URL()` normalises them away, re-attaches `pathBase` so no input can steer a COPY/MOVE outside the volume) + `VolumeRoutes` (`GET|POST /user/volumes` (quota `MAX_VOLUMES_PER_USER`, user-only owner check, private-by-default, `hrefPrefixMode`), `GET|PATCH|DELETE /user/volumes/:owner/:volume` owner-only, `davProp` cache purged when the href mode changes, DO cleanup best-effort) + `CredentialRoutes` (per-bucket credentials) + `UserRoutes` (`GET /user/me`, `GET /users/:username`).
- `ReplicationRoutes.ts` + `replicationProjection.ts` — nine owner-only routes under `/user/volumes/:owner/:volume/replications`, all through `VolumeScopedRoute(404)`. **Owner-only and never credential-reachable is the security design, not a routing detail**: a credential grants content access to one bucket, so letting it also name a remote URL would be exfiltration — point a victim's bucket at an attacker-controlled host, let `sync`/`keep-both` push the owner's files there, read them. Replication is a configuration surface about *where this bucket's contents go*, so it rides on the identity that owns the bucket. 404 rather than 403 so a stranger cannot probe which buckets exist, let alone which have targets. `POST .../run` answers `202` and finishes in `waitUntil` (a slice is bounded but is still tens of seconds, and a client timeout would read as a failed sync that had succeeded), awaiting inline only when there is no execution context so a test never asserts against a promise that was never started. `toReplicationJson`/`toConflictJson` are the only thing between a stored credential and a client: every field is named explicitly, so publishing `encrypted_secret` takes a deliberate edit rather than a copied row. `POST .../run` resolves **both** DAOs from the request scope — passing only `replicationDAO` let the runner fall back to `new DavReplicationConflictDAO(env.DB)`, so the conflict-audit rows on that path were written by a DAO that never passed through the scope.

## Auth

- `/user/*` — Cloudflare Access (`DEMO_MODE` → `DEV_AUTH_EMAIL` → JWT → `ctx.access` fallback). Neither bypass is set in `wrangler.template.jsonc`: each authenticates _every_ unauthenticated request as a fixed identity, and `AppConfiguration.validate()` warns if one is present with `ENVIRONMENT=production`. The address is then resolved to an account through the `user_emails` registry, so a user who has changed address lands on the same account; there is deliberately **no** self-service address-change route (see `UserIdentityService` in the backend-services guide).
- WebDAV `/:owner/:volume/*` — bucket-level Basic only (username AND password validated, bound to volume id, expiry enforced). Public buckets allow anon reads; all writes and all private access require a bucket credential. No Bearer, no user-level PAT, no collaborators.
- Read-only credentials: `davAuthForVolume` takes `needWrite` and refuses a write from a `read_only` credential with **403** + a `DAV:error` body and **no** `WWW-Authenticate` (a 401, or a 403 carrying that header, re-prompts a native client forever). The check sits right after the volume-binding check and before the rehash/`last_used_at` writes, so a refused attempt costs no D1 write. Enforcement lives here and nowhere else — the DO has no auth, so a request that reaches it was already allowed. A read-only credential has no owner exemption: `Basic` carries no owner identity, and the browser plane (Access, owner-authenticated) is unaffected.

## Routes

- WebDAV CORS: `applyCors(response, request, SITE_URL)` — allow-list, not origin reflection, plus `Vary: Origin`. Unset `SITE_URL` degrades to same-origin only.
- WebDAV: `OPTIONS` (`Allow` + `DAV: 1, 2`) · `PROPFIND` · `PROPPATCH` · `MKCOL` · `GET`/`HEAD` (Range, HTML browser for collections) · `PUT` · `DELETE` · `COPY`/`MOVE` (`Destination` same-origin, `Overwrite`) · `LOCK`/`UNLOCK` (all in `DavVolumeWorker`, front only auth + forward + CORS).
- Volumes: `GET|POST /user/volumes` · `GET|PATCH|DELETE /user/volumes/:owner/:volume`.
- Credentials: `GET|POST /user/volumes/:owner/:volume/credentials` · `PATCH|DELETE /user/volumes/:owner/:volume/credentials/:id`. `POST` takes `readOnly`; `PATCH` takes `{ readOnly }` and flips it, returning the updated row.
- Users: `GET /user/me` · `GET /users/:username`.
- Public: `GET /` (minimal HTML volume browser) · `GET /health` · `/docs`.

## Composition

- Single scope per request: `scopeMiddleware` installs one `Container` + `ServiceContext`; handlers resolve via `BaseRoute.getScope(c).get(Tokens.X)`.
- `src/endpoints/IBaseRoute.ts` — `BaseRoute` (`readJson` with a _stream_ cap via `readCappedBody`, `getScope`, `toErrorResponse` mapping `ServiceError`; AWS envelope `{Exception:{Type,Message}}`).
- `src/workers/routes/VolumeScopedRoute.ts` — template method for every `/user/volumes/:owner/:volume/...` handler: one ownership guard (`isVolumeOwner` on the account key, never the address), 404-vs-403 as a constructor argument (the browser plane hides existence, the credential plane does not), one error mapping. `requireUser` reads the identity `/user/*` middleware already stored, as `{ email, userId }`.
- Never import `@durable-dav/backend-data/dao` values in routes (type-only allowed); never import `@durable-dav/dav-store` directly — use `@durable-dav/webdav` constants + DO `fetch`.
