**Mock patterns**:

- DAOs/services: in-memory fake D1 implementing `prepare().bind().first/all/run` with per-table arrays; assert via state, not `vi.mock` (composition test is the exception — it mocks the DAO module with `vi.hoisted` fns).
- Credential hashing: real `DavCredentialUtil.hashPassword` (PBKDF2-HMAC-SHA256, 100k iterations, per-hash salt) with ephemeral random passwords. Tests assert the salt/verify contract, never hash determinism; the legacy unsalted-SHA256 format is still accepted and reports `needsRehash` for the migration path. Expiry via `TimestampUtil` arithmetic.
- Access auth: stub env (`DEV_AUTH_EMAIL`/`DEMO_MODE`); never trust `Cf-Access-Authenticated-User-Email`.
- Integration: `test/integration/vitest.config.mts` + `wrangler.test.jsonc` pool, shared migration seeding; `helpers/setup.ts` (`setupIntegrationTest`/`ensureUser`/`seedVolume`/`mintCredentialForVolume`) + `helpers/migrations.ts` (`splitSql`/`applyMigrations`/`migrationFileNames`). Migrations are injected two ways: flattened as `__INTEGRATION_MIGRATION_SQL__` and per-file as `__INTEGRATION_MIGRATION_FILES__`. `applyMigrations` applies **one file per `db.batch()`** and takes a `{from, to}` range, because an upgrade test must be able to stop at 0003, seed the pre-0004 shape, and then apply 0004 to it — a single flattened batch makes that impossible. `ensureUser`/`seedVolume` write the post-0004 columns (`users.id`, `current_email`, `user_emails`, `owner_user_id`); a seed that skipped them would model a state the migration never produces and the id-keyed assertions would pass for the wrong reason.
- **Integration setup runs in `beforeAll`, never per test.** D1 is *not* isolated per test in `@cloudflare/vitest-pool-workers`, and 0004's `ALTER TABLE users ADD COLUMN id` is not re-runnable, so calling `applyMigrations` a second time in one file fails with `duplicate column name: id`. Seed once in `beforeAll` and give each test its own path/credentials/handles. (`CredentialAuth.int.test.ts` reads as if it re-seeds per test; it actually calls its `ensureVolume` from the first test only.)
- **`wrangler.test.jsonc` declares a `CACHE` KV namespace on purpose.** Without the binding, `KvCache.available` is `false` and every read falls through to the DO, so the read cache is *inert* and every cache-key or cache-poisoning bug is invisible to the whole integration suite — the paging-isolation suite passed with the bug present until this was added. Any assertion about caching, `ETag`/`304`, or cross-request staleness has to be written knowing the cache is live.
- **Prove a regression test fails without its fix.** For each hardened bug, revert the fix, watch the new test go red, then restore. A green test against the old code is a test that asserts nothing. This caught two tests here that passed either way (the memo-sharing one asserted the binding rather than the consumer; the cache-poisoning one ran without a KV binding).
- Schema upgrades: `UserIdentityUpgrade.int.test.ts` is the pattern for a data migration — apply through the file *before* it, seed a row in every table reachable by a cascade, apply the migration, then assert no row loss, `PRAGMA foreign_key_check` empty, correct backfills, pre-existing foreign keys still intact (via `PRAGMA foreign_key_list`), and that the new behaviour holds afterwards. `PRAGMA foreign_key_check` reports violations as rows rather than raising, so it must be asserted, not assumed. An **additive** migration needs a different assertion set, since there is no row loss and no FK to dangle — the only failure mode is a wrong *default*. `ReadOnlyCredentialUpgrade.int.test.ts` therefore asserts the default direction (every pre-existing credential lands on `read_only = 0`, and so does an insert that omits the column), the `CHECK` rejecting an out-of-set value, and a round trip. Getting that default backwards locks every existing user out of their own bucket with no error and nothing to diagnose it from. Upstream fix: `dofs@0.1.0` ships an uncompiled decorator example in `dist/index.js` that the pool workerd rejects with a bare `SyntaxError`; stripped via `patches/dofs@0.1.0.patch` (`pnpm-workspace.yaml` `patchedDependencies`) — re-check on every `dofs` bump, drop the patch once upstream ships compiled dist.
