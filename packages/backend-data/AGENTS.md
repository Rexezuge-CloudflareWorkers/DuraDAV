# Durable-DAV — Backend Data (D1/DAO Layer)

Scope: `packages/backend-data/**`. Parent index: `../../AGENTS.md`.

- All D1 access via DAOs over `D1Queryable`: `BaseDAO` (`withRetry` + `firstWithRetry` + `deleteRowsOlderThan`), `UserDAO` (`createUser`/`newId`/`newAnchor`/`getById`/`getByCurrentEmail`/`setCurrentEmail` + `getByEmail` (anchor-only) + `username` via `ensureUsername`/`setUsername`/`getByUsernameCi`), `UserEmailDAO` (address registry: `get`/`resolveVerified`/`register`/`listByUserId`/`revoke`/`revokeAllVerified`), `NamespaceDAO` (global `user` registry: `claim`/`claimIgnore`/`release`/`isTaken`, writes `user_id` beside `user_email`), `DavVolumeDAO` (`getByOwnerName`/`getById`/`listByOwnerUserId`/`countByOwnerUserId`/`listByOwnerEmail`/`countByOwnerEmail` (pre-0004 fallbacks)/`update`/`renameOwner`, case-insensitive `owner_ci/name_ci`), `DavCredentialDAO` (`getActiveByUsername`/`updatePasswordHash`/`listByVolume`/`countByVolume`/`usernameExists`/`updateLastUsed`/`deleteForVolume`/`deleteByVolume`/`pruneExpired`).
- **Identity columns (0004)**: `users.id` + `users.current_email`, `user_emails` registry, `dav_volumes.owner_user_id`, `namespaces.user_id`. `UserRow.id`/`current_email` and `DavVolumeRow.owner_user_id` are **optional** — absent on a database where 0004 has not run, which is why the `*ByOwnerEmail` methods still exist. `users.email` is a frozen anchor: `UserDAO.getByEmail` is an anchor/attribution lookup, **not** a login lookup, and an account that has changed address is not findable there by its new one. `UserDAO.newAnchor()` returns `anchor-<hex>@users.invalid` for the case where a free-to-use login address is still held as a *previous* holder's anchor (`.invalid` is RFC 2606 and can never be delivered to, so it can never authenticate).
- **`users.username` is stored lowercase** (`UserDAO.normalizeUsername`, applied inside `setUsername`/`ensureUsername` rather than by each caller): the column carries no `COLLATE NOCASE` and every read lowercases its *parameter*, so a stored `Alice2` is a different value from `alice2` and the handle becomes permanently unfindable — `GET /users/alice2` 404s, the dashboard link breaks, and re-submitting the same name hits the case-insensitive equality short-circuit and reports 200 while changing nothing. `USERNAME_PATTERN` carries `/i`, so mixed case validates and only the write point prevents it. `createUser` uses an **untargeted** `ON CONFLICT DO NOTHING`, because `users` carries two unique constraints (`email`, `idx_users_current_email`) and SQLite applies `DO NOTHING` only to the constraints a named target covers — naming `email` turned a `current_email` collision into a 500 that skipped the opaque-anchor retry entirely.
- The `owner_user_id` / `user_id` foreign keys are declared `ON DELETE CASCADE` deliberately. A bare `REFERENCES users(id)` defaults to NO ACTION and would *restrict*, turning a previously-cascading `DELETE FROM users` into a hard failure. Both references cascade together.

- Email/username predicates lowercase the _parameter_, never the column. `lower(col)` makes the index on that column unusable, and every writer already stores lowercase. Credential lookup is by the globally unique `username`, never by `password_hash` — passwords are salted, so no hash can be searched on; the worker verifies against the loaded hash.
- Utils: `D1Types` (`D1Queryable`), `D1Utils` (`executeD1WithRetry`), `D1ErrorClassifier` (retryable detection; re-exports `isMissingSchemaError`, which actually lives in `@durable-dav/shared/utils` because `dav-store` needs it too and the two Layer 2 packages may not import each other). **Retryable is checked first**: a message matching both lists is transient. Reads go through `firstWithRetry`, never a bare `.first()`: writes always used `withRetry`, but point reads used to call `.first()` directly, which rejects with a raw `D1_ERROR` that is *not* a `DatabaseError` — making every documented `DatabaseError` contract on a read path (`DavAuth`'s 503 on auth) unreachable and surfacing a D1 blip as an opaque 500. `firstWithRetry` normalizes the throw to `DatabaseError` and reuses `D1_RETRY_DEFAULTS` so the read and write backoff schedules cannot drift; `first()` resolving to `null` is "no row", a success, and only a rejected statement is retried. The non-retryable patterns are deliberately narrower than their obvious spelling — bare `/range/i` also matched `RangeError: Maximum call stack size exceeded`, and bare `/not\s+found/i` also matched `host not found`, so a DNS blip classified as permanent, was not retried, and surfaced as a 401/500 where a 503 was right.
- Fail-closed rule: a caller may degrade to `[]` or a fallback query **only** on `isMissingSchemaError(error) === true`; every other SQL error must rethrow. `dav-store`'s `getDeadProperties` is the live example — it used to catch everything, which reported a corrupt DO as "this resource has no dead properties".
- Migrations in `migrations/0001_init.sql` (baseline: `users`/`namespaces`, `dav_volumes` + legacy token tables) + `migrations/0002_bucket_credentials.sql` (`dav_credentials`, `dav_volumes` rebuilt with `DEFAULT 1` private-by-default, drops `user_access_tokens`/`token_scopes`/`token_volume_grants`/`dav_collaborators`) + `migrations/0003_href_prefix_mode.sql` (`ALTER TABLE dav_volumes ADD COLUMN href_prefix_mode TEXT NOT NULL DEFAULT 'base' CHECK(IN ('base','root'))`) + `migrations/0004_user_identity.sql` (account key; additive and rerunnable — every backfill guarded by `IS NULL`/`INSERT OR IGNORE`). Integration embeds them two ways: flattened as `__INTEGRATION_MIGRATION_SQL__` and per-file as `__INTEGRATION_MIGRATION_FILES__`; `applyMigrations(db, {from, to})` applies one file per `db.batch()` so a test can seed the *pre*-0004 shape and then upgrade it.
- 0004 is additive by necessity, not preference: D1 honours neither `PRAGMA foreign_keys = off` nor `PRAGMA legacy_alter_table = on`, and `defer_foreign_keys` does not suppress `ON DELETE CASCADE` — so `dav_volumes.owner_email`'s reference to `users(email)` cannot be repointed at `users(id)` without losing rows. `users.email` therefore stays, immutable, as the anchor every legacy `*_email` value resolves against.
- `href_prefix_mode` is `TEXT` with a `CHECK`, so reads coerce through `readDavHrefPrefixMode` (shared) rather than a cast: a row predating the column, or a value the `CHECK` should have prevented, must keep serving the conforming `base` shape instead of failing every DAV request. Writes validate with the strict `toDavHrefPrefixMode`/`isDavHrefPrefixMode` so a bad API value is a 400, not a constraint 500.
- Credential prune path: `DavCredentialDAO.pruneExpired(now, limit)` (batched `DELETE` via `BaseDAO.deleteRowsOlderThan`) called from `apps/background`'s `ExpiredCredentialPruningTask` on the `*/10 * * * *` cron. The batch size is the caller's argument, not a DAO constant.
- **Replication: `DavReplicationDAO` + `DavReplicationConflictDAO` + `replicationPassSql`.** `pass_started_at IS NOT NULL` is the **deletion gate**, and `replicationPassSql` is where that is stated rather than in the DAO methods: while a pass is open an absence is not evidence of anything, so the planner defers every absence-based decision. It closes on a *failed* pass and on a *clean and complete* one, and deliberately stays open on a clean pass that still has queued collections — clearing the column only on failure left it set for the life of the target, so a healthy replication never propagated a deletion at all. `recordRun`'s auto-disable is one statement because a read-then-write races two concurrent ticks and lets both see `consecutive_failures = max - 1` and each decide it was the last straw. `listDue` spells its order `COALESCE(last_run_at, 0)` rather than `NULLS FIRST`: the never-run rows sort first either way, but the portable one does not depend on the SQLite version D1 ships this month. `cursor_remaining` counts paths still to visit, not bytes — it is the only number available before a slice has read anything, and the staleness guard compares it against zero to decide whether the pass ended cleanly.
- Layer 2 (L0-only): import only `@durable-dav/shared` + `@durable-dav/backend-errors`; never `backend-runtime`, `backend-services`, or `apps/*` (enforced by `no-restricted-imports`).
